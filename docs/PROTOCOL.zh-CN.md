# 协议笔记（小米 MJGJD01YL / Telink TLSR8368）

[English](PROTOCOL.md) | [简体中文](PROTOCOL.zh-CN.md)

> **来源说明：** 数据包格式、CRC 参数、指令码和配对方法来自 [lamperez/xiaomi-lightbar-nrf24](https://github.com/lamperez/xiaomi-lightbar-nrf24) 的逆向研究。本文补充使用 nRF24L01 串口桥接时的实现细节；实现中的错误由本项目负责。

## 数据包（17 字节）

| 偏移 | 字节数 | 字段 |
| ---: | ---: | --- |
| 0 | 8 | 前导码 `53 39 14 DD 1C 49 34 12`，各灯具相同 |
| 8 | 3 | 挂灯已绑定的遥控器编号 |
| 11 | 1 | 分隔符 `0xFF` |
| 12 | 1 | 序列计数器 |
| 13 | 2 | 指令 `cmd1 cmd2` |
| 15 | 2 | CRC16，大端序 |

上游项目的 README 文字与代码对计数器和指令的顺序描述不一致；本固件按其代码及抓包顺序，把计数器放在偏移 12、指令放在偏移 13–14。

## CRC 与数据白化

CRC16 参数为 `width=16 poly=0x1021 init=0xFFFE refin=false refout=false xorout=0x0000`，计算范围为字节 0–14。发送时数据按原样传输，不使用软件白化。

## 无线与 nRF24 帧格式

- 使用 2 Mbps GFSK；关闭 nRF24 硬件 CRC 和自动应答。
- 发送地址 `55 55 55 55 55` 用作同步序列，而不是常规意义上的设备地址；包含前导码在内的完整 17 字节数据包作为 nRF24 载荷发送。
- 使用信道 6、43、68，分别对应 2406、2443、2468 MHz。
- 每条逻辑指令使用同一个数据包和计数器，在三个信道各重复 20 次，以提高接收概率。
- 读取原遥控器时，接收帧对齐方式参考 [lightbar2mqtt](https://github.com/ebinf/lightbar2mqtt)，并检查前导码和 CRC。

## 序列计数器

挂灯用偏移 12 的 1 字节计数器去重：相同计数器会被当作同一次操作，新的计数器会被当作新操作。因此，一次重复发送应保持计数器不变，而不同操作应改变计数器。

串口打开可能重置 Nano。固件每 16 条指令把计数器检查点写入 EEPROM；启动时跳过 16 个值并立即保存新的起点，避免中途重置后重复最近一次计数，同时减少 EEPROM 写入。

## 指令码

| 操作 | cmd1 | cmd2 |
| --- | --- | --- |
| 开关切换 | `0x01` | `0x00` |
| 调冷 +N | `0x02` | `0x01`–`0x0F` |
| 调暖 −N | `0x03` | `0xFF`–`0xF1` |
| 调亮 +N | `0x04` | `0x01`–`0x0F` |
| 调暗 −N | `0x05` | `0xFF`–`0xF1` |
| 重置 / 配对 | `0x06` | `0x00` |

应用的 0–15 档滑块先发送超出范围的 16 步降低指令，使灯具到达最低端，再发送目标档位对应的增加指令。灯具不会对这两条指令应答，所以界面显示的是目标值，不是确认后的状态。

## 配对

挂灯通电后的短时间内，可以接收带有某个 3 字节编号的重置指令并绑定该编号：设置编号、给挂灯断电重启，然后在应用提示的时间内发送配对指令。挂灯闪烁通常表示已绑定；绑定新编号可能使原遥控器暂时失效。恢复方式见[中文使用说明](../README.zh-CN.md#备选配对电脑)。

## 串口协议（115200 8N1）

协议按行发送文本：

```text
SCAN / SCAN_STOP              开始 / 停止读取遥控器编号
SNIFF1 / SNIFF2 / SNIFF_STOP  1 Mbps / 2 Mbps 诊断接收
ID AA:BB:CC                   设置并保存遥控器编号
GET_ID                        读取已保存编号
CMD HH HH                     发送原始指令字节
ON / OFF / RESET / PAIR       切换 / 重置 / 配对
BRIGHT +N|-N / WARM +N|-N     按步数调节亮度 / 色温
```

常见回复为 `READY`、`OK`、`ERR <msg>` 和 `FOUND:AA:BB:CC`。
